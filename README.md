# 비밀번호 보안 도구 (`26-w12-password`)

> 이 README는 실습을 완성한 뒤, 배포 직전 단계에서 직접 채워 넣습니다.
> 실습 안내와 완성 기준은 [`guide.md`](./guide.md)를 참고하세요.

## 소개

브라우저 안에서 비밀번호 강도를 점검하고, `crypto.getRandomValues()` 기반 생성기로 안전한 비밀번호를 만듭니다. Have I Been Pwned의 range API를 사용해 유출 여부도 확인합니다. 라이트·다크 테마를 선택할 수 있으며, 입력한 비밀번호는 저장하지 않습니다.

## Vite 프로젝트 직접 구성 경험

- 기존 템플릿과 달리 `create-vite`로 React JavaScript 프로젝트를 직접 구성하고, `npm install`과 `gh-pages` 설치 및 배포 설정을 진행했습니다.
- Vite scaffold가 `README.md`를 기본 안내문으로 바꾸므로 회고 양식은 `README.template.md`에서 복원했습니다. `.gitignore`에는 `.env`, `.env.*`를 추가하고 `.env.example`은 예외로 두었습니다.
- VS Code의 Go Live는 JSX를 변환하지 못하므로 Vite 개발 서버(`npm run dev`)로 실행해야 했습니다.

## 나의 AI 기획·구현 과정

- **AI 협업 방식**: VS Code + GitHub Copilot으로 기능을 나누어 구현하고, 실행 결과와 보안 동작을 확인했습니다.
- **앱의 정체성**: 강도 검사·안전한 생성·유출 확인을 모은 비밀번호 점검 대시보드로 구성했습니다.
- **강도 기준**: 길이(8·12·16자), 문자 종류(소문자·대문자·숫자·특수문자)를 점수화하고, 4자 이상 반복·연속 패턴과 대표 패턴은 감점합니다. 강도 검사는 브라우저 안에서만 수행합니다.
- **유출 확인 UX**: 입력 중에는 요청하지 않고 사용자가 버튼을 눌렀을 때만 조회합니다. 해시는 대문자 기준으로 비교하고, `Add-Padding: true` 응답의 0회 항목은 유출 기록으로 세지 않습니다.
- **선택한 확장 기능**: `Add-Padding`으로 응답 크기 분석을 어렵게 했습니다. AES 암호화 금고는 이번 범위에 포함하지 않았습니다.

## 보안 점검 (사이버보안과 체크포인트)

### Network 탭 검증 결과

- 검증용 공개 예시 `password`로 확인한 요청: `GET https://api.pwnedpasswords.com/range/5BAA6`
- 요청 경로에는 SHA-1 해시 앞 5글자만 포함되며, 비밀번호와 전체 해시는 전송하지 않습니다. 응답의 나머지 해시 대조는 브라우저 안에서 수행합니다.
- 서버는 요청한 5글자 접두사와 IP 주소, 요청 시각을 볼 수 있으므로 완전한 익명은 아닙니다.

- `Math.random()`은 보안용 난수로 적합하지 않아 생성기에는 `crypto.getRandomValues()`를 사용합니다.
- Network 탭에서 확인한 요청은 위 검증 결과와 같이 SHA-1 접두사 5글자만 포함했습니다. 비밀번호와 전체 해시는 전송하지 않습니다.
- 서버는 접두사와 IP 주소, 요청 시각을 볼 수 있으므로 k-익명성은 비밀번호 자체를 숨기지만 요청 사실까지 숨기지는 않습니다.

## 나만의 확장 기능

`Add-Padding: true` 헤더로 HIBP 응답에 패딩을 적용하고, 응답 목록의 0회 항목은 유출 횟수로 처리하지 않습니다. 강도 검사에는 반복 문자와 숫자·영문·키보드 행의 연속 패턴 감점을 추가했습니다.
