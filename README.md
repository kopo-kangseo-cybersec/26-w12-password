# 비밀번호 보안 도구 (`26-w12-password`) — CyberPass

> 12주차 실습: 빈 저장소에서 Vite 프로젝트를 직접 구성하고, k-익명성(k-Anonymity)과 CSPRNG 원리를 적용한 사이버보안 특화 비밀번호 감사 및 생성 도구입니다.

---

## 소개

**CyberPass**는 웹 브라우저 환경에서 동작하는 차세대 비밀번호 보안 점검 및 k-익명성 감사 대시보드입니다.
- **실시간 강도 및 엔트로피 진단기**: 입력된 비밀번호를 외부 전송 없이 브라우저 메모리 상에서 실시간 분석 (엔트로피 bits, 브루트포스 크랙 시간, 취약 패턴 감지)
- **CSPRNG 암호 생성기**: `crypto.getRandomValues()`를 활용한 암호학적으로 안전한 무작위 비밀번호 생성 (길이, 문자셋, 혼동 문자 제외 옵션)
- **k-익명성 유출 점검기**: Have I Been Pwned API를 통해 SHA-1 해시의 앞 5글자만 전송하여 유출 이력을 안전하게 조회
- **네트워크 감사 패널 (Network Inspector)**: "최소 전송 원칙"이 어떻게 지켜지는지 5단계 시각화 뷰를 통해 직접 검증

## Vite 프로젝트 직접 구성 경험

1. **Vite 프로젝트 직접 구성 소감**:
   - 지금까지는 선생님이 미리 세팅해 둔 템플릿에서 코드만 작성했지만, 이번 실습에서는 `npm create vite@latest .`를 통해 React(JavaScript) 환경을 빈 저장소에 처음부터 직접 차렸습니다.
   - 빌드 도구의 역할(Vite의 빠른 HMR과 Rollup 기반 빌드)과 배포를 위해 필수적인 설정(`vite.config.js`의 `base: './'`, `package.json`의 `deploy` 스크립트 및 `gh-pages`)이 왜 필요한지 원리를 명확히 체득할 수 있었습니다.
2. **`.gitignore` 보강과 보안 습관**:
   - `create-vite`가 자동으로 생성한 `.gitignore`를 확인해 보니 `*.local`만 제외되어 있고, 실제 민감 정보가 들어갈 수 있는 `.env` 파일 자체는 추적 차단되어 있지 않았습니다.
   - 보안 개발자의 기본 원칙에 따라 `.env`, `.env.*`, `!.env.example` 규칙을 직접 추가했습니다. 이번 도구는 무료 공개 API를 써서 키가 없지만, "프로젝트를 차릴 때 비밀 파일 차단부터"라는 보안 습관의 중요성을 다시 확인했습니다.

## 나의 AI 기획·구현 과정

1. **AI 협업 방식**:
   - **Antigravity IDE Implementation Plan 방식**을 선택하여 진행했습니다. 먼저 프로젝트 목표와 보안 제약사항(TypeScript 금지, Math.random 금지, 평문 전송 금지, 5자리 접두사 전송 및 대문자 대조)을 설계 아티팩트로 명문화하고 승인받은 뒤 단계별로 구현했습니다.
2. **비밀번호 "강도"의 기준**:
   - 단순 글자 수 체크를 넘어, 정보 이론의 **엔트로피(\(E = L \times \log_2(R)\))**를 계산하여 정량적 복잡도(bits)를 산출했습니다.
   - 고성능 크래킹 시스템(초당 100억 회 대입) 기준의 무차별 대입 예상 소요 시간(초, 분, 일, 년, 백만 년)을 제공합니다.
   - 연속된 숫자(`123`), 키보드 패턴(`qwerty`, `asdf`), 동일 문자 3회 연속(`aaa`), 흔한 취약 단어(`password`, `admin`)를 정규식으로 감지하여 점수를 감점하는 실무형 알고리즘을 적용했습니다.
3. **구현 중 가장 막혔던 문제와 해결**:
   - **해시 대소문자 매칭 함정**: Have I Been Pwned API 응답의 해시 접미사는 모두 대문자(Uppercase)입니다. 브라우저에서 계산한 SHA-1 16진수 문자열을 대문자로 변환하지 않으면 일치 항목을 찾지 못하고 "유출되지 않음"으로 오판하는 문제가 발생할 수 있어, `toUpperCase()` 변환을 철저히 적용했습니다.
   - **Add-Padding 헤더 대응**: 응답 패딩 기능 적용 시 유출 횟수가 `0`인 허위 레코드가 섞여 들어오므로, 대조 시 `count > 0`인 유효 레코드만 판별하도록 로직을 정교화했습니다.

## 보안 점검 (사이버보안과 체크포인트)

1. **비밀번호 생성에 `Math.random()` 대신 `crypto.getRandomValues()`를 써야 하는 이유**:
   - `Math.random()`은 의사난수 생성기(PRNG)로, 내부 알고리즘(V8 엔진의 xorshift128+)과 시드 값이 시간이나 시스템 상태에 기반하므로 공격자가 이전 난수 출력을 관찰하여 다음 값을 수학적으로 예측할 수 있습니다.
   - 반면 `crypto.getRandomValues()`는 암호학적으로 안전한 의사난수 생성기(CSPRNG)로, 운영체제 커널의 하드웨어 엔트로피 풀(마우스 움직임, 인터럽트 타이밍 등)을 사용하여 난수 시퀀스를 공격자가 예측하는 것이 불가능합니다.
2. **유출 확인 시 Network 탭에서 확인한 실제 요청 주소**:
   - 비밀번호 `password` 검사 시 실제 전송된 요청 주소:
     `https://api.pwnedpasswords.com/range/5BAA6`
   - **최소 전송 원칙 검증**:
     전체 해시 `5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8` 중 **앞 5글자(`5BAA6`)만** URL 경로에 포함되어 전송되었습니다. 사용자의 평문 비밀번호나 나머지 35글자 해시는 요청 헤더, 쿼리, 페이로드 어디에도 일절 포함되지 않았습니다.
3. **k-익명성 방식으로도 서버가 알 수 있는 정보 (완전한 익명이 아닌 이유)**:
   - 서버는 요청자의 **IP 주소**, **요청 시각**, 그리고 **해시의 앞 5글자(접두사)**를 여전히 볼 수 있습니다.
   - 앞 5글자는 약 1,048,576(\(16^5\))개의 카테고리 중 하나를 가리키므로, 서버는 "이 IP의 사용자가 5BAA6으로 시작하는 수백 개의 해시 중 하나에 관심이 있다"는 사실은 알 수 있습니다.
   - 따라서 k-익명성은 비밀번호의 기밀성을 완벽히 보호하지만, "유출 검사를 시도했다는 행위 자체"까지 숨겨주는 완전 무정보 상태는 아닙니다.

## 나만의 확장 기능

1. **`Add-Padding: true` 요청 헤더 적용**:
   - API 요청 시 패딩 헤더를 활성화하여 응답 바이트 크기로 특정 비밀번호의 유출 여부를 추론하려는 사이드 채널 공격(Side-channel attack)을 차단했습니다.
2. **인포메이션 엔트로피(bits) & 브루트포스 크랙 시간 측정**:
   - 정보 엔트로피 공식을 기반으로 초당 100억 회 대입 시 크래킹에 걸리는 현실적인 시간을 계산해 직관적으로 표시합니다.
3. **키보드 시퀀스 및 취약 패턴 분석 엔진**:
   - 단순 글자 수 외에도 `123`, `qwerty`, `asdf`, 동일 문자 3회 연속 등 취약한 패턴을 실시간으로 감지하고 경고합니다.
4. **네트워크 감사 패널 (Network Inspector)**:
   - 개발자 도구를 켜지 않아도 앱 내부에서 [평문 비밀번호 0% 전송] -> [앞 5자리 해시 분할] -> [실제 전송된 5자리 URL] -> [서버 수백 개 응답과 로컬 대조] 과정을 단계별 시각 자료로 검증할 수 있습니다.
5. **라이트 모드 / 다크 모드 듀얼 테마 지원**:
   - 상단 헤더의 테마 토글 버튼을 통해 주간/야간 환경에 맞춘 최적화된 시각적 대비를 제공합니다.
