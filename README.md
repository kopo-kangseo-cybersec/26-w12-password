# 비밀번호 보안 도구 (`26-w12-password`)

> 실습 안내와 완성 기준은 [`guide.md`](./guide.md)를 참고하세요.

## 소개

**사이버보안 분석가의 비밀번호 보안 진단 및 생성기 대시보드(Password Security Suite)** 컨셉으로 기획·구현한 웹앱입니다.
입력한 비밀번호의 강도와 취약 패턴을 **100% 브라우저 로컬 환경**에서 실시간 분석하고, **k-익명성(k-Anonymity)** 원리를 적용해 평문 비밀번호 노출 없이 실제 유출 이력을 조회하며, 암호학적으로 안전한 난수 기반 비밀번호를 즉시 생성할 수 있는 통합 보안 도구입니다.

## Vite 프로젝트 직접 구성 경험

1. **템플릿 저장소와의 차이점**: 11주차까지는 `package.json`, `vite.config.js`, `src/` 구조가 이미 세팅된 저장소에서 시작했지만, 이번 주에는 빈 저장소에서 `npm create vite@latest .` 명령으로 프레임워크(React), 언어(JavaScript), 린터(Oxlint)를 직접 선택하고 `gh-pages` 배포 스크립트와 `base: './'` 경로 설정까지 수동으로 구성하면서 프로젝트 초기 아키텍처와 빌드 파이프라인이 어떻게 연결되는지 명확히 이해할 수 있었습니다.
2. **`README.md` 및 `.gitignore` 덮어쓰기 경험**: 기존 파일이 있는 디렉터리에서 스캐폴딩 도구를 실행할 때 `Ignore files and continue` 옵션을 선택해 `.github`와 `guide.md`를 보존하고, 덮어써진 `README.md`를 기존 회고 양식(`README.template.md`)으로 복원하는 과정을 겪으며 초기화 단계의 파일 관리 중요성을 체감했습니다. 또한 기본 `.gitignore`에는 `*.local`만 차단되어 있어 실수로 환경변수 파일이 커밋되는 사고를 막기 위해 `.env`, `.env.*`, `!.env.example` 규칙을 최우선으로 보강했습니다.

## 나의 AI 기획·구현 과정

1. **AI 협업 방식**: **Gemini 웹에서 기능 명세와 보안 요구사항을 먼저 설계한 뒤, VS Code의 GitHub Copilot(Agent 모드)으로 코드를 구현**하는 방식을 선택했습니다. 기획 단계에서 구현 기준과 보안 제약사항을 구체적인 프롬프트로 정리한 덕분에 시행착오를 크게 줄일 수 있었습니다.
2. **비밀번호 강도 판별 기준**: 단순 길이만 보는 것이 아니라 **길이(12자 이상 권장), 문자 종류 조합(대문자·소문자·숫자·특수문자), 추정 엔트로피(bits)**를 종합해 5단계(`매우 약함` ~ `매우 강함`)로 산출하도록 설계했으며, `1234`, `qwer`, `password` 등 흔한 패턴이나 동일 문자 연속 반복을 탐지해 경고를 띄우도록 기준을 세웠습니다.
3. **구현 중 해결한 문제**: HIBP Range API가 반환하는 해시 접미사(뒤 35글자)는 **대문자**로 제공되기 때문에, 브라우저의 Web Crypto API(`crypto.subtle.digest('SHA-1', ...)`)로 생성한 해시 문자열을 `.toUpperCase()`로 변환해 비교하도록 처리했습니다. 또한 타이핑할 때마다 불필요한 API 요청이 발생하지 않도록 `'유출 여부 조회'` 버튼 클릭 시에만 최소 요청이 전송되게 UX를 설계했습니다.

## 보안 점검 (사이버보안과 체크포인트)

1. **`crypto.getRandomValues()`를 사용해야 하는 이유**: `Math.random()`은 내부 상태(시드)를 기반으로 예측 가능한 의사난수(PRNG)를 생성하므로 공격자가 생성 패턴을 역추적할 위험이 있습니다. 반면 `window.crypto.getRandomValues()`는 운영체제가 제공하는 암호학적으로 안전한 난수 생성기(CSPRNG)를 사용해 예측 불가능한 비밀번호를 만들 수 있습니다.
2. **Network 탭 실제 요청 주소 및 전송 검증**:
   - 실제 요청 URL: `https://api.pwnedpasswords.com/range/5BAA6`
   - 검증 결과: 개발자 도구(`F12`) → **Network** 탭의 `Headers`에서 확인한 결과, 입력한 비밀번호(`password`)의 SHA-1 해시(`5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8`) 중 **앞 5글자(`5BAA6`)만 URL 경로로 전송**되었으며, 평문 비밀번호와 나머지 35글자 해시는 외부로 전혀 전송되지 않았습니다.
3. **k-익명성 방식의 한계 (완전한 익명이 아닌 이유)**: 비밀번호 원문과 전체 해시는 숨길 수 있지만, 외부 API 서버는 여전히 **조회 요청이 발생한 사실 자체**, **요청자의 IP 주소**, **요청 시각**, 그리고 **해시 앞 5글자(prefix)**를 확인할 수 있으므로 네트워크 메타데이터 수준에서의 완전한 익명성까지 보장되지는 않습니다.

## 나만의 확장 기능

- **`Add-Padding: true` 헤더 적용 및 패딩 필터링**: HIBP API 요청 시 `Add-Padding: true` 헤더를 포함해 서버 응답 크기를 균일화함으로써 응답 패킷 크기만으로 유출 여부를 유추하는 트래픽 분석 공격을 방어하고, 응답 본문에 섞여 들어오는 유출 횟수 `0`인 가짜 패딩 항목을 브라우저에서 필터링하도록 구현했습니다.
- **흔한 패턴 탐지 및 추정 엔트로피(bits) 시각화**: 단순 문자 길이 외에도 `1234`, `qwer`, `password` 등 사전/키보드 패턴과 연속 반복 문자를 탐지해 경고하고, 문자셋 크기 기반 추정 엔트로피(bits)를 실시간으로 계산해 보여줍니다.
- **모호한 문자 제외 생성 옵션 & 메모리 비저장 원칙**: 생성기에서 가독성을 해치는 문자(`0`, `O`, `1`, `l`, `I`)를 제외하는 옵션을 추가했으며, 입력한 비밀번호를 `console.log`나 `localStorage`/`sessionStorage`에 일절 남기지 않도록 구현했습니다.
