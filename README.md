# 비밀번호 보안 도구 (`26-w12-password`)

> 이 프로젝트는 한국폴리텍대학 강서캠퍼스 사이버보안과 12주차 실습 결과물입니다.  
> 외부 서버로 단 한 글자의 비밀번호 원문도 전송하지 않는 **k-익명성(k-Anonymity)**과 **Web Crypto API**를 활용한 웹 보안 도구입니다.

---

## 소개

- **컨셉**: **비밀번호 점검 및 보안 진단 대시보드 (Password Security Inspector & Toolkit)**
- **주요 기능**:
  1. **실시간 비밀번호 강도 검사기**: 브라우저 로컬에서 길이, 4종 문자 조합, 엔트로피(Bits), 취약 패턴(연속 키보드 배열, 사전 단어, 반복 문자)을 실시간 분석.
  2. **안전한 비밀번호 생성기 (CSPRNG)**: `Math.random()`을 배제하고 `crypto.getRandomValues()`만을 사용하여 예측 불가능한 안전한 난수 비밀번호 생성.
  3. **k-익명성 기반 유출 확인**: Have I Been Pwned API를 연동하여 SHA-1 해시의 앞 5글자만 외부로 전송하고, 브라우저 내부에서 대조하여 실제 유출 여부 및 횟수 확인.
  4. **영지식 AES-256-GCM 암호화 금고 (확장 기능)**: PBKDF2(100,000회) 키 파생 및 AES-GCM 인증 암호화(AEAD)를 시뮬레이션하여 마스터 비밀번호 기반 데이터 보호 체험.
  5. **Network 탭 검증 가이드**: k-익명성의 최소 전송 원칙을 사용자가 개발자 도구(F12)로 직접 확인할 수 있도록 도해와 전송 감사 패널 제공.

## 나의 AI 기획·구현 과정

1. **AI 협업 방식**:
   - **Antigravity IDE (Gemini 3.8 Flash)**를 통해 전체적인 보안 아키텍처 및 구현 계획(Implementation Plan)을 수립한 뒤, 컴포넌트별로 모듈화하여 점진적으로 구현하고 Oxlint 및 Vite 빌드로 실시간 검증을 거쳤습니다.
2. **비밀번호 "강도"의 기준**:
   - **길이 가점**: 8자 미만(위험), 8자 이상(보통), 12자 이상(안전), 16자 이상(매우 안전).
   - **문자 다양성**: 대문자(A-Z), 소문자(a-z), 숫자(0-9), 특수문자(!@#$...) 포함 개수에 따른 조합 점수.
   - **정보 엔트로피(Entropy)**: 문자 풀 크기와 길이를 기반으로 $L \times \log_2(N)$ 공식을 적용해 bits 단위 엔트로피 산출.
   - **취약 패턴 페널티 감점**: 키보드 연속 패턴(`qwerty`, `asdf`), 숫자 연속열(`1234`), 흔한 단어(`password`, `admin`, `secret` 등), 동일 문자 4회 이상 연속 반복 검출 시 감점 및 경고 메시지 표시.
3. **구현 중 가장 막혔던 문제 및 해결**:
   - **대소문자 대조 불일치 이슈**: HIBP range API의 반환값은 35자리 **대문자 Hex 해시** 접미사 목록입니다. 브라우저에서 계산한 SHA-1 해시를 대문자로 변환하지 않고 비교하면 실제 유출된 비밀번호(`password`)도 '미유출'로 잘못 판정될 위험이 있었습니다. 이를 방지하기 위해 로컬 해시 접미사와 서버 응답 모두 `.toUpperCase()`로 엄격히 정규화하여 대조하도록 구현했습니다.
   - **Add-Padding 가짜 응답 처리**: 패킷 크기 기반 트래픽 분석을 차단하기 위해 `Add-Padding: true`를 적용할 때 유출 횟수가 `0`인 가짜 패딩 레코드가 응답에 포함될 수 있습니다. 대조 시 `count > 0`인 유효 항목만 유출로 인정하도록 로직을 방어적으로 작성했습니다.

## 보안 점검 (사이버보안과 체크포인트)

1. **`Math.random()` 대신 `crypto.getRandomValues()`를 써야 하는 이유**:
   - `Math.random()`은 유사 난수 생성기(PRNG)로, 내부 알고리즘(V8 엔진의 xorshift128+ 등)의 이전 출력값 몇 개만 알면 다음 난수를 수학적으로 정확히 역산할 수 있습니다. 공격자가 생성된 비밀번호 패턴을 예측할 수 있으므로 암호학적 용도로는 절대 사용할 수 없습니다.
   - 반면 `crypto.getRandomValues()`는 운영체제 커널의 하드웨어 인터럽트, 키보드/마우스 입력 노이즈 등 물리적 무작위성을 수집하는 엔트로피 풀을 사용하는 **암호학적으로 안전한 의사 난수 생성기(CSPRNG)**이므로 다음 값을 예측하는 것이 불가능합니다.
2. **Network 탭에서 확인한 실제 요청 주소**:
   - 대표 테스트 케이스 (`password` 검사 시):
     ```
     Request URL: https://api.pwnedpasswords.com/range/5BAA6
     Request Method: GET
     Status Code: 200 OK
     Request Headers: Add-Padding: true
     ```
   - **검증 결과**:
     - `password`의 SHA-1 전체 해시는 `5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8`입니다.
     - 외부 네트워크로 전송된 것은 앞 5자리인 `5BAA6`뿐이며, **원문 비밀번호(`password`)나 나머지 35글자 해시는 일절 외부로 전송되지 않았음**을 개발자 도구 Network 탭에서 확인했습니다.
3. **k-익명성 방식으로도 서버가 알 수 있는 정보 (완전한 익명이 아닌 이유)**:
   - 서버는 요청을 보낸 클라이언트의 **IP 주소**, **요청 발생 시각**, 그리고 조회한 **해시 접두사 5글자(`5BAA6`)**를 액세스 로그를 통해 알 수 있습니다.
   - 비밀번호의 본문은 완벽하게 보호되지만, "이 IP 사용자가 특정 시점에 비밀번호 유출 여부를 조회했다"는 행위 자체와 대략적인 해시 버킷 그룹은 서버가 관측할 수 있습니다.

## 나만의 확장 기능

1. **`Add-Padding: true` 헤더 지원 및 패딩 필터링**:
   - HIBP API 조회 시 응답 크기(Payload Size)를 통한 사이드 채널 트래픽 분석 공격을 방어하기 위해 가짜 패딩 데이터를 요청하는 헤더를 탑재하고, UI에서 사용자가 직접 토글 및 효과를 이해할 수 있도록 구성했습니다.
2. **영지식(Zero-Knowledge) AES-256-GCM 암호화 금고 시뮬레이터**:
   - 사용자가 입력한 비밀번호로부터 PBKDF2(100,000회 반복, SHA-256, 16바이트 CSPRNG Salt)를 통해 256비트 암호화 키를 도출하고, AES-GCM(12바이트 CSPRNG IV)으로 기밀 메모를 인증 암호화(AEAD) 및 복호화하는 실습 패널을 제작했습니다.
3. **Network 전송 내역 시각화 감사(Audit) 패널**:
   - 비밀번호 검사 직후 실제 전송된 5글자와 로컬에 은닉된 35글자, 그리고 실제 전송된 URL을 카드 형태로 분리 표기하여 학생 및 평가자가 직관적으로 보안성을 검증할 수 있도록 구현했습니다.
